# T6 - Integration UI (rapport)

## Resume
L'application a une branche « SWTOR » dans l'arbre de gauche : zones du catalogue par categorie (filtre), rooms avec cases a cocher et triangles par room,
total + jauge du budget BSP, nom de carte, puis Preview / Import / Export / Create PK3 par `SwtorWorkflowSteps`. KOTOR 1/2 inchange.
`dotnet build Kotor2Ja.sln` : 0 avertissement, 0 erreur. `dotnet test Kotor2Ja.sln` : **660 reussis, 0 echec** (84 + 183 + 179 + 107 + 41 + 66 ; 9 tests ajoutes + 2 tests sur ressources reelles). Rien commite. Jeu non lance, base JA non touchee (tests dans un dossier temporaire).

## Fonctionnalites
1. **Branche SWTOR** (`Ui/SwtorPanel.cs`) : catalogue lu du cache JSON du dossier de travail dans une tache de fond (reconstruit s'il est absent), groupes Planets / Story / Ships / Flashpoints...,
   libelle « nom affiche - nom interne », info-bulle (id, rooms, modeles), filtre (id, noms, categorie, planete). Branche masquee si `<racine>/world/areas` n'existe pas.
   Racine : cle `swtorAssetsDir` de `kotor2ja.config.json` (ajoutee, valeur livree `C:\jka_tor_assets\resources`), variable `SWTOR_ASSETS` prioritaire, sinon defaut de `SwtorAssets`. `ExportOptions.SwtorDir` (null = defaut) ; la CLI `export-swtor` l'utilise aussi si `--assets` est absent.
2. **Rooms** : `SwtorAreaAnalyzer` construit la zone une fois en tache de fond (sans collision, espace inclus) pour compter les triangles de rendu par room (tri decroissant ; `skyscene` non listee car jamais exportee).
   Cases a cocher (room « space » decochee par defaut), boutons Default / All / None, total `N / 174 750 triangles (~index / 524 288)`, vert / orange (>= 85 %) / rouge + « WARNING » si depasse (estimation = 3 x triangles + 36 index de ciel, valeur mesuree en T5), nom de carte (defaut = celui de la CLI, suffixe de rooms si sous-ensemble ; valide avant l'apercu). Aucune room cochee : Preview desactive.
3. **Etapes** : `Swtor.Pipeline/SwtorWorkflowSteps` (module = `id[:room1,room2]`) ; `GameWorkflowSteps` aiguille KOTOR / SWTOR derriere un seul `WorkflowController`. Code partage : `SwtorExporter.Prepare` (chargement + validation des rooms + scene) sert a la CLI (`Export` refactore) et a l'application ;
   Import / Export / Create PK3 reprennent `KotorWorkflowSteps` via la nouvelle methode `UseScene` (aucune logique dupliquee). L'apercu utilise `PreviewRenderer` tel quel. Codes de journal affiches comme pour KOTOR (`CODE: message`, au plus 3 par code puis « ... and N more »), plus `SWTOR_BSP_BUDGET`.
   Les limites BSP du compilateur (`BSP_ERROR`, `COLLISION_CAPPED`...) remontent par le meme journal / message d'erreur. Pk3 verrouille (jeu ouvert) : erreur `PK3_LOCKED` claire (fermer le jeu, recliquer), etape conservee, pas de plantage (teste avec un fichier verrouille).
4. **Automatisation** : `--game swtor --module <id>[:room1,room2] --run-to preview|import|export|pk3 --camera ... --screenshot ... --exit` ; en SWTOR la virgule separe les rooms (pas de selection multiple). Avant la capture, l'application attend le catalogue et la liste des rooms. Attention : `--run-to pk3` ecrit dans `jaBaseDir` de la config.
5. **Tests** (`Swtor.Pipeline.Tests/WorkflowUiTests.cs`) : modele de selection (defaut, sous-ensemble, spec, nom), niveaux et estimation du budget, branche masquee / zone inconnue / assemblage refuse / nom invalide, config `swtorAssetsDir` (priorite env, save), aiguillage composite, et sur ressources reelles (SkippableFact) : analyse de la zone du Conseil noir, workflow complet jusqu'au pk3 dans un dossier temporaire + pk3 verrouille.

## Utilisation
Lancer l'app, deplier SWTOR, choisir une zone (filtre possible), cocher les rooms (surveiller le total), eventuellement changer le nom de carte, Preview, puis le bouton Import / Export / Create PK3 en bas a droite.
Ligne de commande : `Kotor2Ja.App.exe --game swtor --module 4611686142106770000:station_dark_council_chamber --run-to preview --screenshot x.png --exit`.

## Limites
- L'analyse des rooms construit la zone entiere (quelques secondes, davantage pour une grande zone) puis l'apercu la reconstruit (pas de cache partage).
- Dans la zone du Conseil noir (138 rooms), la room demandee par l'automatisation est cochee mais la liste, triee par triangles, peut la placer hors de la vue (defilement).
- Pas de champ « dossier SWTOR » dans le panneau Settings (cle de config / variable d'environnement seulement) ; options CLI `--world-scale`, `--include-space`, `--axes` non exposees dans l'interface (la room « space » se coche a la main).
- Nom de carte non pilotable par l'automatisation. Assemblage de plusieurs zones SWTOR non pris en charge.
- Premier lancement sans cache : reconstruction du catalogue (quelques secondes) en fond, le reste de l'interface reste utilisable.
