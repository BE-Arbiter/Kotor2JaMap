# T2 - Rétro-ingénierie des zones SWTOR (area.dat / room .dat)

## Ce qui fonctionne
- `src/Swtor.Core/Areas/` :
  - `AreaDatReader` / `AreaDat` : rooms, table d'assets (id 64 bits → chemin), propriétés d'ambiance (`AreaProperties` : `is_outdoor`, `skyscene_room`, lumières statiques, brouillard, `environment_map`...), points d'arrivée (`AreaMarker`, balayage heuristique).
  - `RoomDatReader` / `RoomDat` / `RoomInstance` : objets avec `Id`, `TypeId`, `AssetPath` (résolu par la table d'assets), `Kind` (Model, Light, FxPlaceable, Portal, Trigger, Region, Heightmap, Cover, Spawn, Engine, GameData, Other, Unknown), parent, position, échelle, rotation Euler (degrés), couleur de lumière, tous les champs bruts (`RoomField`), rooms liées. Types d'asset hors table → `Unknown` (jamais d'exception) ; type de champ inconnu / taille incohérente → `GameFormatException` avec offset.
  - `AreaLayout` : charge une zone complète, `World(instance)` compose les transformations parent/enfant (anti-cycle), `ResolveFolder(id|dossier)`. `AreaTransforms` : convention Euler et matrice locale.
- CLI `kotor2ja swtor-dump-area <id|dossier> [--assets racine] [--max N]` (`SwtorDumpAreaCommand`) : rooms, marqueurs, propriétés, comptes par type, % de gr2 trouvés, bbox des origines, N premières instances par room (chemin + position/rotation/échelle + monde si parent + couleur des lumières).
- Spec en français : `docs/superpowers/specs/swtor-formats.md` (layout binaire, niveaux de confiance, sources/licences).
- Parcours complet : **267 zones / 16 640 fichiers de room, 0 échec**, 4 627 430 objets, 2 860 567 modèles gr2 dont **100,00 % présents sur disque** (25 543/25 560 chemins distincts ; 17 manquants), 99,99 % des références de parent résolues, 352 objets de type inconnu seulement.

## Hiérarchie / composition
Le champ `parent` (hash `0x40865E7F`) référence l'`id` d'un autre objet. Position/rotation/échelle d'un enfant sont locales au parent : `M_monde = S·R·T(enfant) × M_monde(parent)` (vecteur ligne System.Numerics). Les enfants sont typiquement des renforts/panneaux attachés à un pilier ou un cadre de porte, ou des fx. Le `typeId` d'un objet est directement l'asset (gr2 ou classe moteur) : pas d'indirection.

## Inconnus et risques
- **Convention d'Euler** : angles en degrés, +90° sur Y envoie +X vers -Z ; ordre retenu X puis Y puis Z (`qx*qy*qz`). Confiance moyenne : la majorité des rotations sont des lacets purs, les rotations multi-axes (`(0,±90,±90)`, `(±90,±90,0)`, `(0,90,180)`) ne se départagent pas par les tests statistiques tentés (recouvrement d'AABB, contact enfant/parent). À valider visuellement en T4/T7, éventuellement en changeant `AreaTransforms.RotationFromEuler`. La main (gauche/droite) du moteur n'est pas tranchée.
- **Échelle** : l'architecture `spc_arch_ss`, `all_all` et exterieure est en mètres (module 3,2 m), mais les intérieurs de vaisseaux joueurs `spc_ps_*_int_*` et les pièces de stronghold sont modélisés à environ 1/5 (porte 0,73 × 0,47) : un facteur est appliqué ailleurs (non trouvé : peut-être dans les champs inconnus de l'objet parent ou dans le code). Ne pas utiliser ces zones pour valider l'échelle.
- Champs inconnus : seuls parent, position, échelle, rotation, couleur de lumière et nom de fxspec sont identifiés. Rien sur visibilité/ombres/collision des modèles, rayon/atténuation des lumières (l'échelle sert d'extension probable), `type 1` (u32).
- Section 2 d'`area.dat` (points d'arrivée) : noms OK, transformations non décodées. Sections 4-8 et bloc final des rooms : non décodés. « Rooms liées » (liste UTF-16 avant la paire finale) = hypothèse de visibilité.
- Terrain : blob zlib de l'objet `heightmap.hms` (en-tête décompressé `02, u32 66, u32 62`), non décodé. Pas d'objets SpeedTree visibles dans les tables d'assets.
- Le dossier d'une zone mélange rooms jouables et rooms annexes (`SPACE`, `skyscene` = ciel, positions `(0,-100,-100)`), à filtrer via la propriété `skyscene_room`.

## Recommandations
- **T3 (id → nom)** : le nom lisible est dans la minimap `map_<nom>_r.dds`, le dernier bloc d'`area.dat` (chaîne « war_planworking ») et le nom de room/mapnotes ; les ids numériques `0x40000006...` sont dans le GOM (`world.areas.*` ?) : T3 doit vérifier. Fallback : nom de la minimap + thème de la majorité des gr2 (`spc_space`, `all_all`, `mak_makeb`, ...). Plusieurs zones n'ont ni minimap ni nom évident.
- **T4 (scène)** : charger avec `AreaLayout.Load`, ne garder que `Kind == Model` pour la géométrie, ignorer la room `skyscene_room`, exclure ou traiter à part `SPACE`. Instancier les gr2 en les posant avec `layout.World(inst)` ; maillage visible = tout mesh dont le nom ne contient pas `collision` (le mesh `generated_collision` sert de collision, T5). Premiers tests sur `4611686045100172646` (kit spc_arch_ss, 3,2 m) : la cible la plus simple. Vérifier l'ordre d'Euler en comparant des murs/poutres tournés. Éviter pour l'instant les zones `spc_ps_*` et strongholds (échelle). Les `gr2` partagent un kit : prévoir un cache modèle → textures.
- **T5** : lumières (`Light`, couleur RGBA, échelle = extension), propriétés d'ambiance d'`area.dat` (`static_light_*`, `light_azimuth/polar`), `Heightmap` blob à décoder pour l'extérieur, `Cover`/`Trigger`/`Portal`/`Spawn` à ignorer pour la géométrie.
- Marqueurs `arrival_*` utiles pour le point d'apparition (transformation à décoder, section 2).
