## Evolution 1 : ventilateurs sans collision

### Constat (mesure sur les 34 niveaux, pas supposition)

- Les ventilateurs sont les things de modele `fan0`, `fan0big`, `fan1` a `angvel` non nul (templates `fan1`, `10fanfast`, `16fan0`, `c3_fan`, `c3_fan0_moving`, `m5_fan0_moving`) : **13 things**
  (01narshadda 4, 10cargo 1, 16aescapeship 2, 16bescapeship 2, m5 1, c3 3). Aucune `PureRotation` dans les `.key` reels (deja note en T6) : il n'y a pas de `misc_model_*` anime en rotation pure parmi eux.
- Les 13 sont deja des `func_rotating` + `model2` dont le sous-modele a le contenu `BspContents.None` (shader `mover_nonsolid`). Verifie sur le BSP compile et dans le moteur (OpenJK-SWGL) :
  `SV_SetBrushModel` met `ent->contents = CM_ModelContents` = 0 ; `SV_ClipMoveToEntities` ignore une entite sans contenu (`clip->contentmask & touch->contents`, sv_world.cpp:753) ;
  `G_MoverPush` ne pousse que si `G_TestEntityPosition(check) == pusher` (g_mover.cpp:406), jamais vrai pour un volume non solide.
  Aucun triangle de collision de decor (`collide=3`, `ExtraSolid`) ne touche la boite d'un ventilateur. Les secteurs des ventilateurs sont fermes par des adjoins franchissables (0x7).
- Donc **sur les donnees actuelles aucun ventilateur n'avait de collision venant du convertisseur**. Deux hypotheses a l'origine du retour utilisateur, non verifiables sans lancer le jeu : un ancien
  `kotor_*.pk3` / export perime dans `base` (voir memoire « stale test pk3 shadowing »), ou une collision de la geometrie du monde autour du ventilateur (conduits solides, hors perimetre).
- Chemin residuel reel dans le code : un thing qui tourne mais dont le modele est trop grand pour un `func_rotating` (`modelscale > 1`, `JK_ROTATION_APPROX`) etait pose en `misc_model_static`
  **avec** collision de face `collide=3`. Aucun des 13 ventilateurs n'est dans ce cas, mais c'etait le seul chemin ou un ventilateur pouvait bloquer.

### Fait
